# NLP Embedding v3: 向量检索规模化与高级训练调优

## 1. 为什么在大规模场景下“暴力”不可行？

在项目的早期阶段，我们实现了基础的向量检索功能。对于 5k 甚至 2w 条数据，使用 PyTorch 纯矩阵点乘或 FAISS 的 `IndexFlatIP`（暴力穷举）几乎是瞬时的。

然而，当数据量跨越到 **百万 (1M) 甚至千万 (10M)** 级别时，我们会面临两个致命瓶颈：

1.  **计算延迟**：查询一个 Query 需要与库中所有向量计算内积。$O(N)$ 的复杂度会让毫秒级搜索变成秒级等待。
2.  **启动代价**：每次重启 Streamlit 都要重新为全量 Doc 跑一遍 RoBERTa 推理。对于 24w 数据，即使有 GPU 也要消耗数分钟，这严重破坏了“即时反馈”的教学初衷。

为此，在 v3 版本中，我们实施了三项重大的工业级架构增强。

---

## 2. 向量落盘缓存：Doc 向量一次计算，长效复用

我们遵循了 **“Query 在线实时编码，Doc 离线预计算”** 的工业范式。

### 2.1 分离存档策略

我们将高维向量张量与文本元数据分开存储，以兼顾存储效率与白盒化可读性：

- **`.npy` 文件**：使用 `numpy.save` 保存原始浮点向量矩阵。
- **`.pkl` 文件**：使用 `pickle` 保存对应的原始语句（Sentences）与标签（Labels）。

### 2.2 命名空间隔离

为了防止多模型共存导致的特征冲突，缓存文件名锚定了所有关键超参：
`doc_cache_{model_type}_{dataset_name}_embed{dim}.npy`
只有当模型架构、语料集合、向量维度完全匹配时，缓存才会生效，确保了语义空间的严谨性。

---

## 3. FAISS 倒排索引 (IVFFlat)：从 $O(N)$ 到 $O(\sqrt{N})$

为了支撑真正的大规模检索，我们将检索算法从暴力穷举升级为了 **倒排文件索引 (Inverted File Index)**。

### 3.1 聚类分桶 (kmeans)

`IVFFlat` 的核心思想是：先对高维空间进行训练（`index.train()`），利用 K-Means 算法在空间中确立 $N$ 个聚类中心（桶）。

### 3.2 动态超参自适应

- **nlist (桶的数量)**：根据语料规模 $N$ 动态设置。通常遵循 $4 \times \sqrt{N}$ 的经验法则。
- **nprobe (探测桶数)**：查询时不再遍历全库，而只去离查询点最近的 `nprobe` 个桶里精排。这让检索耗时从线性增长变成了极其平滑的对数/对数级以下增长。

---

## 4. 极致喂图管线：解决 GPU “空转挨饿”

很多开发者会发现 GPU 占用率极低且训练慢。其真因在于 **CPU 加载与搬运数据的速度跟不上 GPU 算力的消化速度**。

我们在 `data.py` 中实现了三项针对 NVIDIA GPU 的管线补完：

1.  **锁页内存 (Pin Memory)**：启用 `pin_memory=True`。数据加载后被锁定在物理 RAM 的非分页区，允许显卡通过 DMA (直接内存访问) 绕过 CPU 拷贝直取，大幅提升 Host-To-Device 带宽。
2.  **异步多进程预取**：拉起 `num_workers=4`。在显卡处理当前 Batch 梯度的同时，后台子进程在异步准备下两个 Batch 的缓存。
3.  **持久化 Worker**：通过 `persistent_workers=True`，避免每个 Epoch 重新拉起进程的上下文开销。

## 5. 高级微调策略：Warmup + Cosine + Early Stop

在 RoBERTa 等大型预训练模型的精细微调中，我们引入了三位一体的控制逻辑以平衡收敛速度与稳定性。

### 5.1 线性预热 (Warmup)

在训练的前 10% 步数里，学习率从 $1\times10^{-6}$ 缓慢爬升到目标值。这类似于赛车的热胎，有效避免了初始阶段巨大的震荡梯度直接摧毁预训练模型中已经沉淀好的语义连接。

### 5.2 余弦退火 (Cosine Annealing)

在越过峰值后，学习率沿着余弦曲线平滑衰减。这种规律的“降温”能帮助模型越过局部鞍点，最终在该维度的极小值点稳健地停下，从而获得比固定学习率更好的测试集泛化能力。

### 5.3 早停机制 (Early Stopping)

通过监控训练中的 Epoch Loss，我们加入了“耐心”机制（`patience`）。一旦连续两轮（2 epochs）没有出现新的 Loss 历史最低值，引擎将判定模型已完全收敛并强制熔断训练。这不仅防止了过拟合，更极大地节约了训练成本。
